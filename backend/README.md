# Spring Boot Backend Coding Guidelines & Standards

This document establishes the architecture, code style, and engineering standards for the Spring Boot backend service. All developers and AI agents working on the backend must follow these guidelines.

---

## 1. Project Directory & Package Structure

We use the standard Controller-Service-Repository layers pattern under `com.nib.backend`:

- `com.nib.backend.controller`: Rest controllers exposing REST API endpoints.
- `com.nib.backend.service`: Business logic orchestration. Transaction boundaries are defined here.
- `com.nib.backend.repository`: Spring Data JPA repositories.
- `com.nib.backend.model`: JPA entities mapped to the Supabase Postgres database.
- `com.nib.backend.dto`: Data Transfer Objects (Requests & Responses). Use Java **records** for DTOs.
- `com.nib.backend.exception`: Custom exceptions and the global exception handler.
- `com.nib.backend.config`: Beans configuration (Security, CORS, Jackson, etc.).

## 2. REST API Standards

### Controller Design
- Always use `@RestController` rather than `@Controller`.
- Map controllers under `/api/v1` or `/api` as base routes.
- Return structured response wrappers rather than raw types.

### Request Validation
- Validate all incoming payloads. Use `jakarta.validation` annotations (e.g., `@NotNull`, `@NotBlank`, `@Size`, `@Min`).
- Annotate request bodies in controller methods with `@Valid` to enforce verification:
  ```java
  @PostMapping("/documents")
  public ResponseEntity<DocumentResponse> uploadDocument(@Valid @RequestBody DocumentRequest request) { ... }
  ```

### Exception Handling
- Do not let raw database exception stack traces leak to the client.
- Handle exceptions globally using a controller advice:
  ```java
  @RestControllerAdvice
  public class GlobalExceptionHandler {
      
      @ExceptionHandler(DocumentNotFoundException.class)
      public ResponseEntity<ErrorResponse> handleNotFound(DocumentNotFoundException ex) {
          return ResponseEntity.status(HttpStatus.NOT_FOUND)
                  .body(new ErrorResponse("NOT_FOUND", ex.getMessage()));
      }
      
      @ExceptionHandler(MethodArgumentNotValidException.class)
      public ResponseEntity<ErrorResponse> handleValidationErrors(MethodArgumentNotValidException ex) {
          String detail = ex.getBindingResult().getFieldErrors().stream()
                  .map(err -> err.getField() + ": " + err.getDefaultMessage())
                  .collect(Collectors.joining(", "));
          return ResponseEntity.status(HttpStatus.BAD_REQUEST)
                  .body(new ErrorResponse("VALIDATION_ERROR", detail));
      }
  }
  ```

### DTOs & Java Records
- Since we are using Java 21, prefer **records** for DTOs to ensure immutability and reduce boilerplate.
  ```java
  public record DocumentResponse(
      UUID id,
      String filename,
      String storagePath,
      LocalDateTime createdAt
  ) {}
  ```

## 3. Database & JPA Best Practices

### Relational Mapping
- Use `@ManyToOne` and `@OneToOne` with `FetchType.LAZY` (default is EAGER, which can cause performance penalties).
- Avoid bidirectionality (`@OneToMany`) unless strictly necessary; prefer querying the database via repositories using foreign keys.

### Transaction Management
- Annotate service methods that read/write data with `@Transactional`.
- For read-only actions, use `@Transactional(readOnly = true)` to optimize performance and prevent dirty checking.
- Do not place `@Transactional` annotations on controller methods.

### N+1 Query Prevention
- When fetching entities with relations, use `@EntityGraph` or `join fetch` in custom JPQL queries to avoid N+1 queries.
  ```java
  @Repository
  public interface DocumentRepository extends JpaRepository<Document, UUID> {
      @Query("SELECT d FROM Document d JOIN FETCH d.pages WHERE d.id = :id")
      Optional<Document> findByIdWithPages(@Param("id") UUID id);
  }
  ```

## 4. Code Quality & Formatting

### Lombok Usage
- Use Lombok annotations carefully:
  - Prefer `@Getter` and `@Setter` at the class or field level.
  - Use `@RequiredArgsConstructor` for constructor injection (avoid `@Autowired` on fields).
  - Avoid `@Data` on JPA entities because its generated `hashCode()`, `equals()`, and `toString()` methods can cause lazy-loading initialization errors or infinite recursion. Override these manually if necessary.

### Dependency Injection
- Always use constructor injection. This makes code easier to test without reflection.
  ```java
  @Service
  @RequiredArgsConstructor
  public class DocumentService {
      private final DocumentRepository documentRepository; // Inject via constructor automatically generated by Lombok
  }
  ```

### Logging
- Use SLF4J via Lombok's `@Slf4j` annotation.
- Never use `System.out.println()`.
- Log variables using placeholders rather than string concatenation:
  ```java
  log.info("Processing document ID: {}", documentId);
  ```

## 5. Testing Requirements

Maintain a robust test suite for both components and integration scenarios:

- **Unit Tests**: Test utility classes, business rules, and services using JUnit 5 and Mockito.
- **Controller Tests**: Use `@WebMvcTest` paired with `MockMvc` to test controller serialization and validation logic.
- **Repository Tests**: Use `@DataJpaTest` with test containers or in-memory databases to verify custom queries.
- Mock all third-party AI or network integrations during tests.
